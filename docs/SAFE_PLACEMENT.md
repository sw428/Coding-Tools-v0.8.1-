# CSS安全配置 — v0.8.2 β

## 目的

CSS自動配置が繰り返し作業を短縮しても、既存の実装を壊したら意味がない。未検証の構文については編集しない、という **fail-closed** 方針を採る。

## 操作の流れ

1. 既存クラスがあればその位置に移動（書き換えない）。
2. 新規クラスの配置先を判断できたら、**空のCSSルール1件**を作成する。
3. 元のCSSと挿入後のCSSをPostCSSで構文解析する。
4. 追加したルール以外の宣言・セレクタ・@ルール・コメントの構造が変わらないことを検査する。
5. VS Codeの読み取り専用Diffで**変更前 / 変更後**を開く。
6. 最終確認ONの場合、承認ボタンを押したときだけ実際のエディタへ挿入する。
7. Diff表示中に元ファイルが変更された場合は中止する。
8. 通常のエディタUndo (`Ctrl+Z`, macOS `⌘Z`) で挿入を戻せる。操作Diff履歴は従来通り別保存する。

## 安全制限

- 既存ルールの削除・移動・書き換えを実行しない。
- プロパティ入りルールや複数ルールの自動追加を拒否する。
- 挿入前後のCSSに構文エラーがあれば、無編集で中止する。
- 構文解析で既存の順序・ネストが変化すると判定された場合は中止する。
- CSSのみ対応。**SCSS / LESSは自動配置を実行しない。**
- 認識不能・複雑な構文ではあえて止まる（後から検証対象を追加する）。
- `@media`を新規追加する場合も、空のCSSルール1件しか含めない。
- 構文上合法でもブラウザで期待通り表示されるとは限らない。DevToolsでの確認を省略しない。

## 設定と注意

- 最終確認はCoding Toolsの設定画面にある「CSS適用前の最終確認」でON/OFF。初期値ON。
- OFFでも事前解析・Diffプレビュー・変更中の競合防止は省略しない（承認ボタンだけ省略）。
- `settings.json`との履歴設定の双方向同期はまだ未実装。採用済み仕様に混同しない。
- Diffプレビューは動作を模擬した画像ではなく、VS Code内で開く仮想読み取り専用ドキュメントの差分。
- VS Code実機での動作確認は未完了。テスト用ファイルで先に検証する。
