# SPEC — 現行採用仕様と未実装案の境界

> **基準 v0.8.2 β**。現行コードと付属テストに基づく。ユーザー環境での実機検証は未完了。

モジュールIDは [VISION.md](VISION.md) のM01〜M07を共通で使う。M01〜M05は以下に採用仕様を記載し、M06（規約プロファイル）・M07（利用環境の分離）は未実装。

## M01 — ナビゲーション

- HTMLのclass属性は空白区切りのトークン単位で移動。空の値は飛ばす。
- CSSはクラスセレクタを対象に前後へ移動。対象名全体を選択する。
- 前・次のクラス：Windows Ctrl+Alt+J / K。Mac Cmd+Option+J / K。
- クラス上ではCtrl+1が前、Ctrl+2が次のクラス（MacはCmd+1/2）。Ctrl+Tabが次、Ctrl+Shift+Tabが前の同名クラスへ、同じファイル内で循環する。クラス全体の選択にも対応し、補完候補・スニペット・Tabでのフォーカス移動中は上書きしない。
- HTML→CSS：Ctrl+Alt+3。CSS→HTML：Ctrl+Alt+4。
- 共通コマンド「対応するHTML／CSSへ移動」（`codingTools.jumpBetweenHtmlCss`）は、HTML系ならCSSへ、CSS系ならHTMLへ移動方向を切り替える。既存の検索・候補順位・上限・候補移動を共用し、クラス以外では移動しない。初期キーは未割り当てで、ショートカット一覧から任意のキーを割り当てる。専用ボタンや標準の定義プロバイダーは追加しない。
- 複数ファイルのジャンプ候補：最初の候補をエディタで開き、下部の候補表示をクリックして次へ移る。Escで終了。前の候補コマンドは独自キーを割り当てて使える。Tab系はファイル内移動に使う。確認モーダルは出さない。
- クラス名に編集カーソルを置くと、ファイル内とHTML⇄CSS移動の初期キーを行末の簡易ヘルプで案内する。既定2秒、表示OFFと0.5〜30秒の設定に対応。選択肢を確定させる画面ではない。

## M02 — コピーと貼り付け

- コピー保存枠は1・2の2つ。Windows Ctrl+Alt+Shift+1/2でコピー、Ctrl+Alt+1/2で貼る（MacはCmd+Option）。
- 下部ステータスバーは、枠ごとに「(番号) コピー（初期キー） 貼り付け（初期キー） / 保存内容」の順に表示。コピー／貼り付けは直接クリックで実行し、番号や保存内容のクリックでは操作メニューを開く。空枠の操作メニューはコピーのみ。
- 枠1・2それぞれで番号・操作名・初期ショートカットキー・保存内容を独立して表示ON/OFFできる。操作名とキーを両方OFFにするとコピー／貼り付けの表示は隠れる。非表示でも専用キーは動作し、保存内容は消さない。
- 下部の「Coding Tools」は設定全般の入口。表示項目の複数選択、履歴期間、CSS設定、ショートカット、ガイドに進める。全非表示でもこの入口から表示を戻せる。Go Liveより右側に、Coding Tools → 枠1 → 枠2の順で表示する（利用者による表示位置の個別変更を除く）。
- 表示設定はglobalStateに保存し、即時反映する。サイドバーの設定欄からも変更できる。メニューをキャンセルした場合は変更しない。
- 選択したクラス名・ID名、またはカーソル上のクラス名・ID名を、クラスは`.name`、IDは`#name`で保存する。保存文字列・種別・形式タグ・時刻を1つの枠レコードとして更新し、新形式は記号からも種別を確認する。以前の記号なし文字列とclass-slotのフラグも読み取れる。識別子以外の選択はそのまま、未選択なら現在行を保存し、種別を解除する。実行中は最新のレコードを保持し、古いストレージ通知でコピー直後の内容を戻さない。
- 単独の `.name {`／`#name {` は、開始波括弧まで選択しても波括弧を除き、記号付きの名前を保存する。同じ見出し行の空白・`{`・その直後へカーソルを置いてコピーした場合も同じ。クラス／IDの種別は別に保持し、CSSには記号を1つ付け、HTML・検索欄への専用貼り付けには記号なしで渡す。通常のOSクリップボードは変更しない。宣言を含むCSSブロックや、子孫・子・兄弟・カンマで区切られた複数セレクターの選択は通常テキストとして保つ。
- HTMLの同じclass属性の複数クラス、CSSの隣接したクラス／IDからなる複合セレクター（`.js-button.button`など）から通常コピーするときは、接頭辞なしのクラスを1つ優先する。接頭辞の対象は `js-`・`c-`・`p-`・`l-`・`u-`・`is-`・`has-`。名前の接頭辞自体を削ることはしない。優先候補が複数ならカーソル上の候補、なければ先頭を使う。単独クラスの明示選択とID上のカーソルは指定した名前を保つ。子孫・子・兄弟・カンマで区切られた別セレクター、別属性・別要素へは優先範囲を広げない。
- 枠1・2の貼り付けは、CSSのセレクタ入力ではクラス名に`.`、ID名に`#`を1つ付ける。CSSのコメント（/* */、編集中の//）、文字列・宣言値や他言語へはドットを付けない。CSSの構造上の空行では下記の自動配置を行う。一般テキスト・CSSブロックなどは変換しない。SCSS / Lessはその場への貼り付けのみ。
- Coding Toolsのコマンドはすべてコマンドパレットから非表示。下部ボタン・設定・履歴欄のボタン・ショートカットから利用する。旧9〜13の独立した枠選択・クラス名コピー・スマートコピー／貼り付けは削除。
- **通常のCtrl+C / Ctrl+V、MacのCmd+C / Cmd+Vは上書きしない。** 保存枠1・2へのコピーは拡張内部だけに保存し、OSクリップボードを読み書きしない。通常のCtrl+Vは最後に通常コピーした内容を貼り、保存枠の貼り付けは専用キーCtrl+Alt+1/2（MacはCmd+Option+1/2）を使う。

- 検索サイドバーとエディタ内検索（Ctrl+F）の検索語欄では、Ctrl+Alt+1/2（MacはCmd+Option+1/2）で検索語全体を指定した保存枠の文字列に置き換える。`searchInputBoxFocus`／`findInputFocussed`専用の割り当てからVS Codeの検索コマンドへ直接渡し、OSクリップボードも背後のコードも変更しない。エディタ内検索は一度ウィジェットを開いてから検索語を設定し、空の検索欄で背後の選択文字が引数を上書きする動作を避ける。
- 置換などその他の入力欄では、`inputFocus && !editorTextFocus`の別キーバインドからVS Code標準貼り付けへ渡す。標準貼り付けを実行する間だけOSクリップボードの文字列を一時使用し、終了・失敗後は元へ戻す。処理中に新しい通常コピーがあればその内容を保ち、連続する枠貼り付けは直列化する。この汎用ルートの実機での貼り付け完了時期は未検証。

- Windowsでは他アプリのCtrl+Alt+1/2にも対応する補助機能を同梱。拡張内部のON/OFF設定で切り替え、初期値ON。外部には識別子の記号を外して渡す。通常クリップボードの全形式を退避し、取得できない形式があれば中止する。所有マーカーが残っている場合だけ復元し、新しい通常コピーを上書きしない。通常キーやアプリ設定は変更せず、VS Codeが前面なら専用キーも横取りしない。Mac用補助は未実装。詳細と制限は[EXTERNAL_PASTE.md](EXTERNAL_PASTE.md)。

## M03 — コピー元の構造情報

- `html-context.js`がHTMLソースから取得し、コピー枠ごとの`coding-tools.slot-context.1/2`へ文字列と別に保存する。`schemaVersion: 1`で保持形式を識別する。
- クラス名、従来の同一接頭辞の前後クラス、コピー元URI・言語・文書バージョン・トークンの位置を保持する。接頭辞がないクラスでも構造情報を取得する。
- `structure`へ対象要素のタグ・id・クラス・明示role・ソース位置、親・祖先・直接の子、直前／直後の要素兄弟と兄弟内の順番・総数を保存する。子の詳細は先頭32件までとし、総数・省略有無を別途保持する。
- セクショニングはsection / article / nav / asideの入れ子を保持する。main / header / footer / bodyは別の構造領域として扱う。
- 配置判断用の役割として、セクション自身・構造領域・見出し・子を持つ要素・通常要素の区別、所属セクションと領域、兄弟内の位置を保持する。Flex/Gridや画面上の役割をHTMLだけから決めない。
- コピー時点のHTMLソースのスナップショットで、ブラウザ実行後のDOMではない。取得元を`basis: html-source`、取得状況を`source / partial / unavailable`と理由で保存する。テンプレート、未完のタグ、ブラウザ補正を要する構造は完全なDOMとして扱わない。2,000,000文字・10,000要素・深さ128を超える場合は構造情報の取得を中止する。
- 枠1・2は独立して保持し、再読み込み後もglobalStateから使う。一般テキストやCSSクラスをその枠へコピーした場合は、以前のHTML構造情報を消す。通常のクリップボードには構造情報を付加しない。
- コピー元全文は保存しない。`codingTools.copyInformation`で保持項目を選択する。現在OFFにした項目は、以前の保存枠からもM04へ渡さない。従来形式の保存枠も前後クラス情報を引き続き利用できる。
- `overview`に対象クラスの全体での出現数・所属領域数・共用の有無と、section/header/footerの並びを保持する。出現詳細は128件、領域一覧は256件までで省略を記録する。実行後のDOMではない。

## M04 — CSS配置

- コピー枠1・2のクラス名・ID名をCSSの構造上の空行へ貼り付けると、今のCSSファイルで自動配置する。`automaticPaste`の既定はON。候補画面や確認待ちを挟まない。別ファイルへ切り替えない。
- カーソルのある既存の適用範囲、または`placementRules`で指定した範囲を使う。同じ範囲に同じセレクタがあればカーソルに最も近い既存ルールへ移動する。なければ空ルールを追加する。既存の@media / @supports / @container / @layer内への追加に対応する。
- 新規@media作成、任意セレクタの入力、通常貼り付けを選ぶ画面、独立配置・貼り付け方法コマンドは削除。
- 保存枠の前後クラス・直接の兄弟・親のクラス、登録コメント、命名、HTML全体での共用と領域順を選択可能な判断材料にする。構文と挿入前後の構造を検査し、そのまま追加する。処理中にCSSが変更・閉鎖された場合は中止する。既存ルールの移動・変更は行わない。Undoで戻せる。
- `codingTools.sectionCommentTemplate`へ普段のCSSコメント書式を登録する。既定は`/* {name}`＋改行＋`--------------------------------*/`。自動見出しはsection/header/footerを対象とする。header/footerはタグ名、sectionは最も近い領域のクラス名→id→タグ名を入れ、空行を挟んでCSSルールを続ける。asideは通常のクラスルールとして扱い、親子・兄弟関係とasideである情報を内部保持して所属section内の配置判断に使う。article/navも自動見出しの対象外。`sectionComments`で明示的に個別登録したコメントは優先する。同じ範囲に同じコメントがある場合は増やさない。新規メディアクエリは作成しない。
- 空ルールはコメントのまとまり内への追加を既定とする（`codingTools.requireCommentGroup: true`）。対応する目印がなければ登録書式で作り、HTMLにある次の領域の目印より前、または既存条件より前／範囲末尾へ置く。領域も既存のまとまりも不明なら仮置き用の目印を作る。複数領域で使うクラスは「仮置き: 共通」を使う。書式は`provisionalCommentTemplate`で設定できる。CSSコメントに構文上のネストを作るものではない。
- `automaticPaste`をOFFにした場合は従来の候補画面を使い、既存コメントや記述済み条件内の追加先を選べる。コメント追加がOFFで安全に使える既存のまとまりもない場合は編集せず通知する。
- 詳しい設定・JSONCの登録例は [WORKFLOW_SETTINGS.md](WORKFLOW_SETTINGS.md)。役割や詳細度だけからセレクタ・レイアウトを生成する処理は未実装。

## M05 — 履歴と設定

- 履歴はエクスプローラーのCoding Tools履歴欄を直接開き、行を選択して閲覧する。31〜33のパネル移動・一覧選択・最新差分の専用コマンドは削除。Git pushは履歴欄上部のボタンから実行する。

- 拡張機能の操作ごとのDiff、ファイル保存ごとのDiff、**Coding Tools経由で成功したGit push**を別区分で保存。
- 各履歴の保存期間から「OFF（記録しない）」または1〜360日を選択。日数を選ぶと、その期間で記録を開始・再開する。独立した記録ON/OFF行は置かない。初期値：操作30日、保存90日、Git push90日。
- OFFは新しい記録を停止し、保存済みの保持日数は変更しない。期間選択のキャンセルでは設定を変更しない。
- 履歴ON/OFF・保持日数は現行版では**globalState**に保存。利用者のsettings.jsonには書き込まない。
- `codingTools.placementRules` はVS Codeの設定項目として存在し、自動配置の適用範囲（手動モードでは候補の初期選択）に使う。ファイル選択を伴う`codingTools.preferredStylesheet`は削除。

## まだ採用済みの動作ではないもの

- 操作履歴などのON/OFF・保存日数を **UIとsettings.jsonのどちらからも変更・同期**する機能（要実装）。
- CSS解析を複数モジュールに分け、職場プロファイルの規約で制御する機能（設計段階）。
- 外部Gitクライアントで行ったすべてのpushを自動検知する機能（未実装）。

上記の未実装案を新機能として導入する際は `DECISIONS.md` と `CURRENT.md` を更新してからソースを変更する。
