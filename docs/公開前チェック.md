# 公開前チェック — Coding Tools β

**現時点の結論：開発用一式のそのまま公開は推奨しない。** 技術内容の公開は可能。ただし以下の確認後に公開用スナップショットを作る。

## コード・配布物

- [ ] WindowsとMacでVSIXのインストール／再起動／アンインストールを検証した
- [ ] 既存のCtrl+C/Ctrl+VとTabの挙動を含むキーバインド競合を確認した
- [ ] CSS自動配置は誤判定時に編集しないことを再現テストで確認した
- [ ] 変更のUndo、ログ記録、ログ削除の結果を実機で確かめた
- [ ] Git pushコマンドがどのリポジトリへ何を送信するかUI／説明書に明示した
- [ ] 操作Diffやコピー内容に機密が入る可能性、保存先、保持期間をREADMEに明記した
- [ ] 同梱ライブラリのLICENSEと由来を確認した
- [ ] Marketplaceを利用する場合、公開者ID・パッケージ構成・公開規約を確認した

## 非公開データ

- [x] 制作やり取りの**詳細版**をGit管理対象から除外する
- [ ] `git ls-files`で個人の操作Diff・設定値・会話原文が追跡されていないと確認した
- [ ] 既存の**すべてのGitコミット**にAPIキー、個人情報、社内コードがないか確認した
- [ ] 公開可能な画像が実機録画ではなく仮想デモであることを明記した
- [ ] 公開用のREADMEとLICENSEを最終確認した

## 重要な注意

- `.gitignore`は**未追跡のファイル**をGitから除外する仕組み。既に履歴に入った情報は履歴から簡単には消えない。
- プライベートの詳細履歴を作るときはGitに一度も入れない。公開が決まったら、公開用データだけで新しいリポジトリを作る方法も検討する。
- CSSを書き換えるβ版は自動テストだけで安全を断言しない。
- リポジトリを公開することと、VS Code MarketplaceへVSIXを公開することは別の操作。
