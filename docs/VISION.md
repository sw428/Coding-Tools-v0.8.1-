# VISION — Coding Toolsの目的

[データと履歴の扱い](DATA_POLICY.md) / [今後の実装予定](ROADMAP.md)

Coding Toolsは、クラスに特化した、シームレスなコピー・貼り付け・移動を目的とする。HTMLとCSSの行き来やクラス名の受け渡しをつなぎ、情報の整理にかかる負担を減らす。

## 現在の開発段階

現在は、コピー・クラス移動・CSS配置・履歴などの基本機能と、各段階をつなぐ保持情報・モジュールの土台を初期構築している段階。単純な操作で使えることを優先し、配置判断と機能同士の連携を調整している。個人版・企業版の分岐やプロファイル運用は今後の設計対象。

## 個人学習

HTML/CSSの実装で繰り返す探索・コピー・移動・並び替えを補助し、ブラウザ上のレイアウトやカスケードの理解と検証に時間を残す。Diff履歴から誤判定を再現できるようにする。

## 将来の実務・チームワーク

共通エンジンを維持し、職場・案件ごとの命名規約、レイアウト方針、CSSの整理順序やメディアクエリの扱いを設定に分離する。判断基準と例外を視覚的に説明し、認識合わせと再作業のコストを減らす。

## コピーとCSS配置の開発方針

VS Codeの拡張機能APIを利用し、標準のコピー・貼り付けとは別に、2つのテキスト保存枠を提供する。コピーした文字列と、その時点のDOM構造やセクショニングなどの情報を拡張機能側で保持し、CSS作成時にその情報をもとに追加先を判断して自動貼り付けできるよう設計している。

現行版で保持しているのは、クラス名と取得できた前後のクラス名・コピー元情報。これを土台に、保持する構造情報と配置判断を初期構築・調整している。

CSSでは、HTMLのセクショニングとコメントの対応、クラス同士のDOM上の関係、詳細度、親子・兄弟要素のセレクタの書き方を、配置判断の共通の土台として扱うことを目指す。配置の自動判断は調整中。ここに書く方針や構想を、そのまま現行版の対応機能として案内しない。

今後は職場・案件ごとの社内規約に合わせてカスタマイズし、プロファイルとして保存・切り替えできる運用を目指す。設定画面から利用者自身が判断基準を編集できるようにすることも課題とする。

操作と設定を単純に保ち、導入の入口を広くし、個人でも使いこなせることを重視する。初期ショートカットは標準操作への割り込みを避け、他の操作と衝突しにくい組み合わせにする。

## 履歴を本人の改善に使う

作者は利用者のコード・コピー内容・操作履歴を収集しない。履歴は利用者自身の環境に残し、本人が振り返りや改善のために扱う。

本人が必要な記録を選び、GPTなどに渡してレポート作成に使うこと、処理が意図どおりにならなかった場面を簡易な差分履歴から追うこと、個人環境のカスタマイズや機能拡張の材料にすることを想定する。現行版はローカルでの履歴記録・閲覧を提供しており、GPTへの自動送信や自動レポート生成は未実装。

## 個人版・企業版とプロファイル

作者へのデータ収集を行わない共通の基盤から、本人が履歴を活用できる個人版と、履歴収集機能を含めない企業版へ派生させる設計を目指す。そこから各プロジェクトや社内規約に合わせたプロファイルを作成・切り替えできるようにする。

履歴の有無、版の分岐、プロジェクトごとの規約設定を分け、設定画面から個人でも扱える運用を目指す。これらの版・切り替え機能は構想段階。

## 設計原則

1. **標準操作を守る**：Ctrl+C / Ctrl+Vを奪わず、専用操作として提供する。
2. **判断を残す**：自動配置の根拠を確認できるようにし、曖昧なら無断で破壊的変更しない。
3. **役割を分ける**：個人データ、職場データ、拡張機能のコードと仕様を混ぜない。
4. **使えるか測る**：時間、誤操作、Undo、メンテナンス負担で継続可否を決める。
5. **機能は削れる**：不安定な機能は無効化・分離・削除できるようにする。
6. **構想は仕様でない**：実装済み・検証済み・検討中を区別する。
