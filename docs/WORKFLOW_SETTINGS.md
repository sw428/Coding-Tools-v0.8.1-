# 操作ヘルプ・コピー情報・CSSコメントの設定

下部の「Coding Tools」またはサイドバーの設定欄から、次の設定を開ける。

## M01・M02 — クラス名の上で出る簡易ヘルプ

HTML/CSSのクラス名に編集カーソルを置くと、その行の末尾にファイル内移動とHTML⇄CSS移動の初期キーを短く表示する。選択を求める画面ではなく、操作を続けられる案内。

- `codingTools.help.enabled`：行末に出る操作ヘルプ（注釈）の表示ON/OFF。既定はON。OFFでも移動・コピー・貼り付けの操作は使える。
- 切り替え方：下部の「Coding Tools」→「ヘルプの表示・表示時間」→「Help: Enabled」のチェックを付ける／外す。変更はその場で反映される。
- `codingTools.help.durationSeconds`：表示する秒数。既定2秒、0.5〜30秒。
- 同じクラス内のカーソル移動では表示時間を延長しない。別のクラスに移ると、そのクラスの案内を表示する。
- キーを変更した場合は変更後の割り当てを使う。案内内のキーは初期値。

| キー | 同じファイル内の移動 |
| --- | --- |
| Ctrl+2（MacはCmd+2） | 次のクラス |
| Ctrl+1（MacはCmd+1） | 前のクラス |
| Ctrl+Tab | 次の同名クラス |
| Ctrl+Shift+Tab | 前の同名クラス |

末尾・先頭では循環する。クラス名にカーソルを置くか、その全体を選択している間だけ有効。補完候補・スニペット入力・Tabによるフォーカス移動を優先する。クラス以外では標準のキー動作を使う。前／次クラスの初期割り当ては各1件。旧Tab／Shift+TabとCtrl+Alt+J/Kは使わない。ユーザー設定がある場合はそちらが優先される。

HTML→CSSはCtrl+Alt+3、CSS→HTMLはCtrl+Alt+4（MacはCmd+Option）。複数ファイルのジャンプ候補は下部の候補表示をクリックして次へ移る。前の候補へ移るコマンドには必要に応じて独自のキーを割り当てる。

同じキーで行き来したい場合は、下部の「Coding Tools」→「キーボードショートカット一覧」から「対応するHTML／CSSへ移動」を探す。コマンドIDは`codingTools.jumpBetweenHtmlCss`。初期キーは未割り当てなので、自分のキーを1つ割り当て、必要ならマウスからそのキーを送る。HTMLのクラスからCSSへ、CSSのクラスからHTMLへ、同じ処理で移動する。標準の定義移動と既存キーは変更しない。

## M03 — コピー時に何を保持するか

`codingTools.copyInformation`で保持する情報を選ぶ。クラス名自体は必ず保存し、初期状態では次のすべてを保持する。

| 値 | 保持する情報 |
| --- | --- |
| `source` | コピー元URI・言語・文書バージョン・トークン位置 |
| `neighbors` | 同じ接頭辞を持つ前後のクラス名 |
| `relations` | 対象要素、親・祖先・子、前後の兄弟と順番 |
| `sectioning` | section/article/nav/asideと、header/footer/main/bodyなどの領域 |
| `roles` | HTML構造上の役割。セクション・見出し・子を持つ要素など |
| `overview` | 対象クラスのHTML全体での出現数・所属領域・section/header/footerの並び |

変更後のコピーから選択した項目だけを保存する。すでに保存した枠の旧情報は次のコピーまで残るが、現在OFFにした項目は貼り付け判断へ渡さない。空配列ならクラス名だけを保持する。情報と文字列は枠ごとに独立して拡張内部へ保存し、通常のクリップボードは変更しない。枠の内容を貼るときは専用キーCtrl+Alt+1/2（MacはCmd+Option+1/2）を使う。

構造はHTMLソースから取得したスナップショット。実行後のDOMやCSSによる表示上の役割は推測しない。不完全・テンプレートなどの部分取得情報は、新しい親子・兄弟による配置判断やコメントの自動追加に使わない。

## M04 — 貼り付け時に何を基準にするか

`codingTools.pasteInformation`で利用する判断材料を選ぶ。初期状態ではすべてを有効にする。保存していない情報は使えない。

| 値 | 判断に使うもの |
| --- | --- |
| `neighbors` | 同じ接頭辞の前後クラスに対応する既存CSS |
| `siblings` | 直接の前後の兄弟要素にあるクラスの既存CSS |
| `parent` | 親要素にあるクラスの既存CSS |
| `section` | 登録した書式・個別コメントと、既存CSS内のコメントで区切られた範囲 |
| `naming` | クラス名の部品・接頭辞などに基づく既存CSSのまとまり |
| `overview` | 複数領域での共用判定と、HTMLの領域順に沿うコメントの配置 |

### 選択を挟まない自動貼り付け

既定の`codingTools.automaticPaste: true`では、CSSの構造上の空行へクラス名を貼ると、その場で既存箇所へ移るか空ルールを追加する。候補画面・差分プレビュー・確認待ちは挟まない。

1. カーソルのある既存の適用範囲、または配置設定の範囲を使う。基本ルールを操作しているときに別のメディアクエリへ自動で移さない。
2. 同じ適用範囲に同じセレクタがあれば、最も近い既存箇所へ移る。
3. コピー元のsection/header/footerに対応するコメントを使う。目印がなければ登録書式で作る。HTMLで後に続く領域のコメントがあればその前へ、なければ既存の条件ブロックより前または範囲末尾へ追加する。
4. コメントの範囲内では前後クラス → 直接の兄弟 → 命名のまとまり → 親要素の順で位置を探す。複数の同じコメントがあればカーソルに近いまとまりを使う。
5. 領域が分からず、既存CSSからもまとまりを絞れない場合は、仮置きの目印の下へ追加する。同じ名前の仮置き目印は再利用する。

`overview`を保持・利用している場合、複数領域で使う同名クラスは一つのセクションへ寄せず、既定では「仮置き: 共通」に入れる。出現詳細は先頭128件、領域一覧は先頭256件まで保持し、省略を別途記録する。HTML全文や他クラスの全出現一覧は保存しない。

### コメントのグループを使う

既定の`codingTools.requireCommentGroup: true`では、空ルールはコメントから次のコメントまでの範囲へ追加する。CSS構文上のネストを作る意味ではない。

`codingTools.provisionalCommentTemplate`で仮置き用の書式を変更できる。既定は`/* 仮置き: {name}\n--------------------------------*/`。共用クラスは「共通」、それ以外はクラス名のBEM部品名を使う。命名による判断をOFFにすると「未分類」を使う。

`addSectionComments`がOFFで使える既存コメントもない場合は編集を止め、通知する。構文検査に失敗した場合も編集しない。既存コードは移動・変更せず、追加はUndoで戻せる。

毎回自分で追加先を選びたい場合だけ`automaticPaste`をOFFにする。従来の候補画面で既存コメントや記述済み条件内の追加先を選べる。コメントを使わない運用では`requireCommentGroup`をOFFにできる。

`roles`は現在、コピー情報として保持する。役割だけからセレクタやCSS上のレイアウトを生成する規則は未実装。

## 普段のCSSコメントを登録する

基本書式は、1行目に名前を書き、改行して2行目に32本のハイフンと `*/` を置く形。初期設定に登録済みなので、この書式を使う場合は追加の設定は不要。たとえば名前が `course` なら次のようになる。

```css
/* course
--------------------------------*/

.course {
}

.course__title {
}
```

設定JSONでは、名前の差し替え位置を `{name}`、改行を `\n` で表す。書式を自分で登録する場合は、`codingTools.sectionCommentTemplate` に次のように指定する。

```json
{
  "codingTools.sectionCommentTemplate": "/* {name}\n--------------------------------*/"
}
```

> 書き方が分からない場合は、使いたいCSSコメントをGPTに貼り付けて「Coding Toolsの設定に登録できるJSON形式に直してください」と頼んでください。

自動で見出しコメントを付ける対象はsection/header/footer。header/footerはタグ名を使い、sectionは最も近い領域のクラス名 → id → タグ名の順で名前を選ぶ。たとえば`<section class="curriculum" id="feature01">`は`curriculum`になる。本文の見出し文や画像のaltから名前を推測しない。

asideは通常のクラスとしてCSSを書く。asideであることと親子・兄弟関係はM03に内部保持し、配置判断に利用するが、asideという理由だけで見出しコメントを作らない。内側のクラスは、所属するsectionの見出しの範囲で親・兄弟の既存CSSを手がかりに追加する。article/navも内部構造として保持し、自動見出しの対象にはしない。

領域ごとに異なる表記を使いたい場合は`codingTools.sectionComments`へ完成したコメントを個別登録する。設定はVS CodeのJSONC、CSSへ追加する内容はCSSコメント。

```jsonc
{
  "codingTools.help.enabled": true,
  "codingTools.help.durationSeconds": 2,
  "codingTools.copyInformation": ["source", "neighbors", "relations", "sectioning", "roles", "overview"],
  "codingTools.pasteInformation": ["neighbors", "siblings", "parent", "section", "naming", "overview"],
  "codingTools.automaticPaste": true,
  "codingTools.addSectionComments": true,
  "codingTools.requireCommentGroup": true,
  "codingTools.sectionCommentTemplate": "/* {name}\n--------------------------------*/",
  "codingTools.sectionComments": {
    // 個別に変えたい領域だけ登録する。空オブジェクトでも上の書式を使える。
    "#news": "/* お知らせ\n--------------------------------*/"
  }
}
```

- キーはタグ名、`#id`、`.クラス名`。対象クラス自身またはその祖先にあるセクショニング要素・header/footer/main/bodyを内側から探し、各領域でid → クラス → タグの順に照合する。
- 値は`/* ... */`形式のCSSコメント1件。改行を含む書式はJSONC文字列内の`\n`で登録できる。複数コメントやCSSルールを混ぜた値では追加しない。
- `sectionCommentTemplate`を空文字にすると、領域コメントは個別登録のみを使う。領域が不明、テンプレートが空で個別登録もない場合は、利用可能な既存のまとまりまたは仮置き用の目印を使う。
- 同じ追加先の範囲に同じコメントがあれば、コメントを増やさずその範囲へ続けて追加する。コメントの照合では空白・改行・英字の大文字小文字の差を吸収し、既存の表記を保つ。自動貼り付けでは複数の同名コメントからカーソルに近い範囲を使う。
- `codingTools.addSectionComments`をOFFにすると、新しいコメントは付けない。`pasteInformation`の`section`がONなら、登録済みコメントによる既存範囲の判断は引き続き使える。
- メディアクエリは自分で記述する。拡張は新しいクエリーを作らず、カーソルのある記述済み条件内、または配置設定で指定した既存条件内へ追加できる。

同じ設定をユーザー設定とワークスペース設定で使える。個人共通の設定と、会社・案件のフォルダー内の設定を分けられる。M06のプロファイル切り替え自体は未実装。

## M02 — 他のアプリへ貼り付け（Windows）

Coding Toolsの設定欄にある「他のアプリへ貼り付け（Windows）」でON/OFFする。初期値ON。設定は拡張内部に保存し、ユーザー設定へ書き込まない。保存枠はクラスを`.名前`、IDを`#名前`で保持し、外部入力欄には名前だけを渡す。[操作と制限](EXTERNAL_PASTE.md)を参照。Macの外部貼り付けは未実装。
