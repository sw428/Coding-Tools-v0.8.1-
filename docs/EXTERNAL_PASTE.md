# 他のアプリへ保存枠を貼る（Windows）

VS CodeでCoding Toolsを開いている間、Chrome・メモ帳などの文字入力欄へ保存枠1・2を貼れます。初期設定はONです。Chrome用拡張やPythonの追加インストールは必要ありません。

1. VS Codeでクラス名などをCtrl+Alt+Shift+1または2でコピーします。
2. 貼り付け先のアプリの入力欄をクリックします。
3. Ctrl+Alt+1または2で、同じ番号の保存枠を貼ります。

| 保存内容／貼り付け先 | 渡す内容 |
| --- | --- |
| クラス／IDの保存枠 | `.panel`／`#panel`で保持 |
| VS CodeのCSS・SCSS・Lessのセレクター | `.panel`／`#panel`（同じ記号を重ねない） |
| HTML・VS Codeの検索欄・CSSのコメント／文字列／宣言値 | `panel` |
| Chromeなど他のアプリ | `panel` |
| 一般テキストやCSSブロック全体 | 内容を加工しない |

外部アプリでは編集中の言語を判別せず、識別子には記号を付けません。他のエディターのCSS入力欄でも名前だけになります。

## ON／OFF

エクスプローラーの「Coding Tools 設定」→「他のアプリへ貼り付け（Windows）」をクリックします。設定は拡張内部へ保存し、ユーザーのsettings.jsonやkeybindings.jsonは書き換えません。Mac用の外部貼り付けは今回の実装に含みません。

この機能がONの間、外部アプリのCtrl+Alt+1／2は保存枠の貼り付けに使います。通常のCtrl+C／Vやその他のキーは置き換えません。VS Codeが前面にある間は、補助機能が専用キーを奪わず、VS Code側の割り当てを使います。外部用の初期キーは固定で、VS Code側のユーザー割り当てとは連動しません。

## コピー内容の保護と動作範囲

- 貼り付けの間だけ通常クリップボードを一時使用し、読み取り後に元のデータへ戻します。復元までの間に通常Ctrl+Vを押すと、一時使用中の文字列が貼られる場合があります。
- 文字列だけでなく、HTML・画像・ファイル一覧などの元データの形式も退避します。退避できない形式があるときは貼り付けを中止します。
- 復元前に新しい通常コピーがあった場合は、所有マーカーがなくなったことを確認し、その新しい内容を保ちます。
- 入力先が切り替わった場合やCtrl／Altなどを離さない場合は送信を中止します。管理者権限で動くアプリ、独自の入力欄、専用キーを先に捕捉するソフトなどには対応できない場合があります。全アプリでの動作や影響が完全にゼロであることは保証しません。
- 通信は同じWindowsユーザー内の名前付きパイプだけです。ネットワーク通信、コピー文字列のログファイル、Windowsへの自動起動登録は追加しません。
- 補助処理はCoding Toolsが起動・管理します。OFFやすべてのVS Codeウィンドウの終了後はキーを使わなくなり、接続がなくなると約6秒で終了します。貼り付けの復元処理中は復元を優先します。

Windows入力送信の権限制限は[MicrosoftのSendInput仕様](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)を参照してください。

## 検証範囲

自動テストで保存形式・旧形式の読み取り・CSS／非CSSの変換・起動停止を検証しています。Windows上では補助処理のコンパイル、キー監視の登録解除、クリップボードの退避復元、専用の非表示テキスト欄への貼り付け、複数のローカル接続と自動終了を検証しています。Chromeや任意アプリでの物理キー操作、Macの外部貼り付けは未確認です。
