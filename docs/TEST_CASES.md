# TEST_CASES — 検証手順

## 自動テスト

```bash
npm test
```

初期リポジトリ作成時（2026-10-25）、Node.js v22環境で終了コード0、`All tests passed.` を確認。**VS Code実機の保証ではない**。

## CSS配置の重点テスト

- [ ] 候補を確定すると、差分プレビューや追加の確認を出さず空ルールが追加される
- [ ] 最終確認のON/OFF設定が表示されない
- [ ] CSSが不正な場合は追加しない
- [ ] 既存の条件内への追加で、元の宣言や構造が変わらない
- [ ] 候補選択中の変更・閉鎖では追加しない
- [ ] Ctrl+Zで追加を取り消せる

## M03 — コピー情報の重点テスト

- 自動：親・祖先・子・前後の兄弟、セクショニングとmain/header/footerの区別、構造上の役割、同名クラスの出現位置、逆向き選択、枠ごとの独立性、一般テキスト/CSSコピー時の旧情報消去、テンプレート・不完全HTML・解析上限を検査する。
- [ ] HTMLから枠1・2へコピーし、再読み込み後も枠ごとの情報が維持される
- [ ] コピー後に元HTMLを編集しても、保持情報はコピー時点のスナップショットである
- [ ] 下部のGo Liveの右に、Coding Tools → 枠1 → 枠2が表示される
- [ ] 開発方針からM01〜M07の構成図を表示できる

## M01〜M04 — 簡易ヘルプと登録コメント

- 自動：ヘルプの既定2秒・OFF・時間変更・別エディタへの移動・終了時の片付け、保持情報の選択と旧情報のマスク、兄弟/親による配置、登録コメントの優先順位・重複防止・CRLF・不正値の拒否、コメント以外のCSSを混ぜないこと、クエリーを生成しないことを検査する。
- 自動：既定では基本ルールの追加先を既存コメントから選び、その範囲の外へ追加しないこと、コメントがなければ編集しないことを検査する。
- [ ] クラス名へ編集カーソルを置くと案内が出て2秒で消え、入力・選択を妨げない
- [ ] ヘルプをOFFにすると直ちに消え、表示時間の変更も反映される
- [ ] コピーする情報と貼り付け判断の設定をユーザー/ワークスペースごとに変更できる
- [ ] 普段のheader/footer/section用コメントを登録して追加できる
- [ ] 基本ルールでは既存コメントの候補を選べ、コメントがない場合は追加されない

## 通常クリップボードと保存枠の分離

- [ ] 通常のCtrl+Cで文字列Aをコピーし、枠1・2へ別の文字列を保存しても、本文・検索・置換欄のCtrl+VはAを貼る
- [ ] 検索・置換欄の専用キーCtrl+Alt+1/2では指定した枠を貼り、直後の通常Ctrl+VはAを貼る
- [ ] 入力欄への専用貼り付けが失敗した場合もAを維持し、処理中に新しく通常コピーした場合はその新しい内容を保つ

## 検索語欄への保存枠貼り付け

- [ ] 検索サイドバーとCtrl+Fの検索語欄でCtrl+Alt+1/2（MacはCmd+Option+1/2）を押すと、検索語全体が各枠の文字列になる
- [ ] 両枠でクラス名に`.`／`#`／`{`が付かず、背後の文書と通常クリップボードが変わらない
- [ ] 通常Ctrl+Vは通常Ctrl+Cでコピーした文字列を使う

実機APIテスト：隔離した`--user-data-dir`と`--extensions-dir`を指定し、`--extensionDevelopmentPath`にこのリポジトリ、`--extensionTestsPath`に`test/search-input.integration.js`、開くフォルダーに`test/fixtures/search-input`を指定してVS Codeを起動する。結果は環境変数`CODING_TOOLS_TEST_REPORT`のJSONファイル（未指定時はOS一時フォルダーの`coding-tools-search-input-result.json`）へ出す。検索コマンド経路を検証し、物理キー入力は行わない。
