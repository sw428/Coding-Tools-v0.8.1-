# Coding Tools — 制作経緯（公開候補）

> この文書は、開発の目的・技術的判断・変更の経緯を整理したものです。個人の会話原文や操作コード履歴は含めません。公開前に最終確認してください。

## 開発の目的

- HTML/CSSの学習中に繰り返す操作を短縮し、レイアウトの理解やブラウザ検証に使う時間を増やす。
- 判断を伴うCSS配置は根拠が確認できるようにし、不確実なケースでは自動処理を中断する。
- 将来的には案件ごとのコーディング規約をプロファイルとして扱い、開発チームの共通理解と定型作業の効率化を支援する。

## 機能設計の変遷

| 段階 | 方針・変更点 |
| --- | --- |
| 初期 | クラスの前後移動、複数のコピー保存枠を実装 |
| 操作整理 | HTMLのclass属性内をトークン単位で選択、CSSクラスの移動にも対応 |
| コピペ安全性 | 標準Ctrl+C/Ctrl+Vの上書きを廃止し、専用コマンドに分離 |
| CSS配置 | 既存ルールの位置、親子・兄弟、@media等を調査して挿入先を推定 |
| 変更追跡 | 操作時・ファイル保存時・拡張内Git push時の履歴を区別 |
| UI | 履歴一覧からDiff／変更元へ移動。ショートカットはVS Code標準一覧から編集可能 |
| v0.8.0 β | コピー保存枠を2つに整理し、HTML↔CSS相互ジャンプを追加 |
| v0.8.1 β | 複数候補をエディタでTab／Shift+Tabで切り替え、ジャンプ時は確認画面を出さない |
| v0.8.2 β | 既存CSSを編集せず空ルール1件だけを追加。構文チェック、Diffプレビュー、失敗時停止を追加 |

## 安全と保守の原則

- 読み取り操作と編集操作を区別し、編集にはUndoやDiff確認を用意する。
- 外部AIへの送信・機密データの保存を当然の前提にしない。
- 操作ログや個人データはソースリポジトリへ含めない。
- 自動テスト合格と実機検証済みを区別する。
- 同じ規約でも職場・案件によって異なるため、将来的に変更可能な設定として分離する。
